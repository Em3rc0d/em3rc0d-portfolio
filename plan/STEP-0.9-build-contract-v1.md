# 6. Publicability contract

Every artifact/content item receives one internal classification:

```text
PUBLIC
SANITIZED
ABSTRACTED
PRIVATE
```

### PUBLIC

Can be shown directly.

### SANITIZED

Can be shown after removing sensitive identifiers/data.

### ABSTRACTED

Can support a general public story but the underlying company asset cannot be directly exposed.

### PRIVATE

Can support internal portfolio confidence only.

Known caution:

- site mapper work is not freely publishable;
- bookCars-derived professional material requires explicit sanitization/abstraction before any public use.

```text

      ↓

      ↓

      ↓
```

The startup must feel like **ignition**, not waiting.

Recommended total expressive duration: approximately 1.5–2.2 seconds, with reduced-motion/returning-user bypass behavior.

No fake RPM/speed data.

# 12. Global Motion Map

Only six core motion verbs are authorized:

```text
ENGAGE
TRACE
ALIGN
LOCK
OPEN
TRANSFER
```

Examples:

### Home → AutoPulse

`01 / AUTOPULSE` persists/locks while context transfers into the case.

### Architecture

Selected component engages; relevant links trace; unrelated nodes recede; inspector opens.

### Evidence

Evidence ID transfers into an inspection sheet without losing case context.

### Paper transition

Carbon environment transfers into Paper evidence material for proof-heavy sections.

Motion that cannot explain state, hierarchy, relationship, or navigation should be removed.

# 13. Responsive Contract

## Desktop

- strong asymmetry;
- inspectable architecture;
- persistent case context where useful;
- pointer hover may expose secondary detail;
- wide artifacts can cross the grid deliberately.

## Mobile

- not a compressed desktop;
- hover interactions become tap/focus;
- architecture exposes a simplified readable path first;
- evidence viewer can become full-screen;
- chapter navigation becomes compact/explicit;
- large editorial typography remains controlled and readable;
- mechanical atmosphere cannot consume content space.

## Reduced Motion

Provide equivalent hierarchy/state without transformational choreography.

# 14. Accessibility Contract

Before visual polish is accepted:

- keyboard navigation works;
- visible focus states exist;
- color is not the only state carrier;
- Carbon and Paper contrast pass readable standards;
- diagrams have semantic/alternate representations;
- motion respects reduced-motion preference;
- tap targets are mobile-safe;
- evidence remains accessible without hover.

# 16. Technical Architecture Contract

The implementation should be content-driven and statically/SEO friendly.

Recommended architecture:

```text
APP SHELL
├── semantic navigation
├── global material/theme system
├── motion primitives
├── responsive layout primitives
└── evidence inspector shell

CONTENT DOMAIN
├── systems
├── case chapters
├── decisions
├── evidence
├── notes
└── publicability metadata

PRESENTATION
├── Carbon environment
├── Paper dossiers
├── system plates
├── specimens
└── technical notation
```

Implementation stack should favor:

- TypeScript;
- component-based web framework with strong SEO/static generation support;
- content/data defined separately from page composition;
- progressive-enhancement motion;
- minimal runtime dependency surface;
- automated lint/type/build checks.

Exact package versions are selected at BUILD initialization, not invented in documentation.
